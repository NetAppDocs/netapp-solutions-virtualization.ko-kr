= NetApp Console Backup and Recovery Service를 사용하여 VM 백업 및 복원
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Red Hat OpenShift 가상화 환경에서 NetApp Console을 사용하여 VM을 백업하고 복원합니다. 이 절차에서는 NetApp Console의 백업 및 복구 서비스를 통해 Azure Blob Storage 컨테이너를 백업 대상으로 사용하여 백업 및 복원 작업을 생성하고 관리하는 방법을 다룹니다.

NetApp Console은 온프레미스 및 클라우드 환경 전반에 걸쳐 스토리지 및 데이터 서비스를 중앙에서 관리할 수 있도록 지원합니다. 통합 제어, 간편한 운영, 안전한 관리를 제공합니다. 사용자 인터페이스 link:https://console.netapp.com["console.netapp.com"^]에서 액세스할 수 있는 여러 데이터 서비스 및 관리 기능이 있습니다. NetApp Console에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/console-family/["NetApp Console 설명서"]을 참조하십시오.

이 섹션에서는 Kubernetes 워크로드, 특히 OpenShift 가상 머신을 위한 NetApp Backup and Recovery 데이터 서비스에 초점을 맞춥니다. NetApp Backup and Recovery Service를 사용하면 단일 인터페이스를 사용하여 Kubernetes 애플리케이션 및 가상 머신을 검색, 관리, 생성하고 보호 정책을 연결할 수 있습니다. 전체 가이드는 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["NetApp Backup and Recovery 설명서"]을 참조하십시오.



[[backup-and-recovery-workflow]]
== 백업 및 복구 워크플로

. *콘솔 에이전트가 설치되어 있는지 확인하십시오.*
+
OpenShift 클러스터가 실행 중인 환경에 콘솔 에이전트가 배포되어 있는지 확인하십시오. 콘솔 에이전트 설치에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/console-setup-admin/concept-agent-install-options.html#agent-console-deploy["NetApp Console Setup 설명서"]을 참조하십시오.

+
.예시 보기
[%collapsible]
====
NetApp Console에서 스크린샷에 표시된 대로 Deploy Agent를 클릭하고, OpenShift 클러스터가 실행 중인 환경에 에이전트를 배포합니다.

이 예에서는 온프레미스 환경을 선택했습니다. 에이전트 설치 프로그램 URL을 복사하고, curl 명령을 사용하여 vSphere에서 실행 중인 Ubuntu 머신에 에이전트 설치 프로그램을 다운로드한 다음, 설치 프로그램을 실행하여 Console 에이전트를 배포합니다.

URL에 에이전트의 IP 주소를 사용하여 등록하십시오. 자세한 지침은 link:https://docs.netapp.com/us-en/console-setup-admin/task-install-agent-on-prem-ova.html["문서"]을 참조하십시오. 에이전트가 등록되면 아래 스크린샷과 같이 NetApp Console에서 확인할 수 있습니다.

. *OpenShift VM의 백업 및 복구 시나리오를 위한 백업 대상으로 Azure Blob Storage 컨테이너를 설정합니다.*
+
이 예제에서는 Azure Blob Storage를 백업 대상으로 사용합니다. AWS S3, Google Cloud Storage, StorageGRID 또는 ONTAP 객체 스토리지를 백업 대상으로 사용할 수도 있습니다.

+
자세한 내용은 link:https://docs.netapp.com/us-en/data-services-backup-recovery/br-start-setup.html#prepare-the-backup-destination["NetApp Console 설명서"]을 참조하십시오.

+
NetApp Console에서 Azure Blob Storage 컨테이너를 백업 대상으로 검색하려면 Azure 포털에서 다음 정보가 필요합니다.

+
[listing]
----
Application (Client) ID:
Client Secret:
Directory (tenant) ID:
----
+
이러한 값을 얻으려면 Azure 포털에서 다음 단계를 수행하십시오.

+
.. Blob Storage 컨테이너를 생성합니다.
.. 엔터프라이즈 애플리케이션을 생성하고, 해당 애플리케이션에 Blob Storage 컨테이너에 대한 필요한 액세스 권한을 할당합니다. Azure Blob Storage 컨테이너를 백업 대상으로 검색하기 위해 NetApp Console에서 사용할 애플리케이션 ID, 디렉터리 ID 및 클라이언트 암호를 이 애플리케이션에서 가져옵니다.
+
.예시 보기

.... 구독에 리소스 그룹을 생성합니다.
.... 스토리지 계정을 생성한 다음 Blob 컨테이너를 생성합니다.

+
.... Azure 구독에 엔터프라이즈 애플리케이션을 생성합니다.
.... 애플리케이션을 등록합니다. 방금 등록한 애플리케이션의 애플리케이션 ID와 디렉토리 ID를 확인합니다.

. *NetApp Console에서 OpenShift 클러스터를 검색하십시오.*
+
.예시 보기
[%collapsible]
====
이 단계를 수행하려면 OpenShift 클러스터가 실행 중이어야 하며 동일한 환경에 Console 에이전트가 배포되어 있어야 합니다. NetApp Console에서 OpenShift 클러스터를 검색하려면 다음 단계를 수행하십시오.

.. NetApp Console에서 *인벤토리 > Kubernetes*를 선택하고 OpenShift 클러스터의 세부 정보를 입력하십시오.
.. OpenShift 클러스터가 위치한 환경과 동일한 환경에 배포된 에이전트를 선택하십시오.
.. 제공된 명령을 복사하여 Trident Protect를 설치하고, OpenShift 클러스터에서  `oc` 명령을 실행하는 데 사용되는 머신에서 해당 명령을 실행하십시오.
.. Trident Protect가 성공적으로 설치되면 *검색*을 클릭하십시오. NetApp Console은 에이전트를 통해 OpenShift 클러스터와 모든 리소스를 검색하고 사용자 인터페이스에 표시합니다.

.<strong>수정 사항 표시</strong>

[source, yaml]
----
- apiGroups:
  - groupsnapshot.storage.k8s.io
  resources:
  - volumegroupsnapshots
  verbs:
  - get
  - list
  - watch
  - create
  - delete
  - update
  - patch
- apiGroups:
  - groupsnapshot.storage.k8s.io
  resources:
  - volumegroupsnapshotcontents
  - volumegroupsnapshotcontents/status
  verbs:
  - get
  - list
  - watch
  - create
  - delete
  - update
  - patch
- apiGroups:
  - groupsnapshot.storage.k8s.io
  resources:
  - volumegroupsnapshotclasses
  verbs:
  - get
  - list
  - watch

----
