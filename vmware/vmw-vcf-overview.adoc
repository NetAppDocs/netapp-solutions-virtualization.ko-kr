= VMware Cloud Foundation 및 ONTAP으로 프라이빗 클라우드 경험 향상
:hardbreaks:
:allow-uri-read: 
:nofooter:

[role="lead"]
NetApp ONTAP는 VMware Cloud Foundation(VCF)과 통합되어 블록, 파일 및 오브젝트 프로토콜을 지원하는 유니파이드 스토리지 솔루션을 제공합니다. ONTAP의 멀티 테넌시(multi-tenancy) 기능을 통해 기업은 워크로드를 통합하고 관리를 간소화하는 동시에 엔터프라이즈급 데이터 보호 및 가용성을 확보할 수 있습니다. 이 문서에서는 VCF에 대한 개요와 NetApp ONTAP를 사용하여 VCF 환경 내 스토리지 기능을 향상시키는 방법을 설명합니다.



[[introduction]]
== 소개

VCF는 조직이 프라이빗 클라우드 환경을 손쉽게 구축하고 관리할 수 있도록 지원합니다. 기본적으로 VM, Kubernetes, 컨테이너 및 네트워크를 서비스로 제공하며, 셀프 서비스 포털에서 카탈로그 항목으로 다른 서비스를 확장하여 제공할 수 있습니다. NetApp ONTAP을 VCF 내에서 스토리지 솔루션으로 활용함으로써 조직은 워크로드 관리에서 더욱 뛰어난 유연성, 확장성 및 효율성을 확보할 수 있습니다.



[[introduction-to-netapp-ontap]]
== NetApp ONTAP 소개

NetApp ONTAP은 광범위한 제품 라인에 걸쳐 고급 스토리지 기능을 제공하는 포괄적인 데이터 관리 소프트웨어입니다. ONTAP은 소프트웨어 정의 스토리지(SDS)로 제공되며, 주요 클라우드 제공업체를 통한 자체 서비스로도 제공되고, NetApp ASA(블록 최적화 분산 스토리지), AFX(비정형 데이터 분산 스토리지), AFF 및 FAS(통합 스토리지) 플랫폼의 스토리지 운영 체제로도 사용됩니다. ONTAP은 사일로 없이 VMware 가상화를 비롯한 다양한 사용 사례에 걸쳐 고성능 및 저지연을 제공합니다. 컴퓨팅 환경에서 VM을 생성하는 방식과 유사하게, ONTAP은 스토리지 리소스를 생성하고 관리하는 데 사용할 수 있는 스토리지 가상 머신(SVM) 생성을 지원합니다. ONTAP은 NFS, SMB, iSCSI, FC, NVMe/TCP, NVMe/FC 및 NVMe/RDMA를 포함한 다양한 프로토콜을 지원하는 유니파이드 스토리지 솔루션을 제공합니다. 이러한 유연성을 통해 기업은 워크로드를 통합하고 관리를 간소화하는 동시에 엔터프라이즈급 데이터 보호 및 가용성을 확보할 수 있습니다.



[[introduction-to-vmware-cloud-foundation]]
== VMware Cloud Foundation 소개

VMware Cloud Foundation(VCF)을 사용하면 조직은 AI 워크로드, DevOps 또는 기존 VM 기반 워크로드 등 어떤 용도든 VM, Kubernetes 클러스터, 컨테이너, 네트워크 및 스토리지를 서비스 형태로 이용할 수 있는 가상 프라이빗 클라우드를 구축할 수 있습니다.

VCF는 신규 환경에 배포되거나 기존 vSphere 환경을 확장하여 완전한 프라이빗 클라우드를 구성합니다. 컴퓨팅 호스트 집합이 vSphere 클러스터를 구성하고, vSphere 클러스터 그룹은 VCF 도메인을 구성하며, VCF 도메인 그룹은 VCF 인스턴스를 구성합니다. 플릿은 하나 이상의 VCF 인스턴스로 구성됩니다. VCF 프라이빗 클라우드 환경은 하나 이상의 플릿을 사용하여 생성됩니다. 운영 및 자동화는 플릿 수준에서 처리되며, VCF 인스턴스는 배포 단위입니다.

vSphere 네임스페이스는 워크로드에 대한 리소스 제한을 설정하는 데 사용됩니다. vSphere Zone은 해당 영역에서 실행되는 워크로드에 고가용성 및 재해 복구 기능을 제공하는 데 사용할 수 있는 vSphere 클러스터 모음입니다.

image:vmware-vcf-overview-components.png["VMware Cloud Foundation 구성 요소"]

VCF Automation에서 리전은 동일한 NSX 인프라를 공유하는 하나 이상의 VCF 도메인에 속한 vSphere 영역들의 모음입니다. 조직은 하나 이상의 리전에 속한 사용자와 리소스의 논리적 그룹입니다. 조직은 여러 프로젝트로 세분화될 수 있으며, 각 프로젝트는 자체적인 트랜짓 게이트웨이와 외부 연결을 가집니다. 프로젝트는 하나 이상의 네임스페이스를 가질 수 있으며, 프로젝트 내에서 실행되는 워크로드에 대한 격리 및 리소스 할당을 제공하는 데 사용될 수 있습니다.

네임스페이스는 프로젝트 내 리소스 할당을 위한 기본 단위입니다. 각 네임스페이스는 가상 프라이빗 클라우드(VPC)에 매핑되며, 해당 네임스페이스에서 실행되는 워크로드에 대한 격리 및 리소스 할당을 제공하는 데 사용될 수 있습니다.

네임스페이스는 전용 VPC 또는 공유 VPC에 생성됩니다. 전용 VPC는 단일 네임스페이스 전용 VPC이고, 공유 VPC는 여러 네임스페이스에서 사용할 수 있는 VPC입니다. 서브넷은 워크로드가 배포되는 VPC 내에 생성됩니다.

스토리지는 vCenter에 정의된 SPBM(Storage Policy Based Management) 정책에 의해 사용됩니다. SPBM은 워크로드에 필요한 스토리지 요구 사항을 정의하는 규칙 집합으로 생성할 수 있습니다. 데이터스토어는 일반적으로 태그가 지정되어 있으며, 이를 활용하여 다양한 워크로드의 특정 요구 사항에 맞는 스토리지 정책을 생성합니다.

선호도 및 비선호도 규칙이 필요한 워크로드는 vCenter 컴퓨팅 정책을 사용하여 특정 호스트 또는 클러스터에 워크로드를 배치하는 방법을 정의하는 인프라 정책으로 관리됩니다. 인프라 정책을 사용하면 워크로드의 요구 사항에 따라 특정 호스트 또는 클러스터에 워크로드가 배치되도록 할 수 있습니다.



[[vcf-domains]]
== VCF 도메인

도메인은 VCF 내의 기반이 되는 구성 요소로, 리소스를 별개의 독립적인 그룹으로 구성할 수 있도록 합니다.  도메인은 인프라를 보다 효과적으로 구성하여 리소스가 효율적으로 활용되도록 보장합니다.  각 도메인은 자체 컴퓨팅, 네트워크 및 스토리지 요소와 함께 배포됩니다.

image:vmware-vcf-overview-domains.png["VMware 클라우드 도메인"]

VCF에는 두 가지 주요 도메인 유형이 있습니다.

* *관리 도메인* – 관리 도메인에는 VCF 환경의 핵심 기능을 담당하는 구성 요소가 포함됩니다. 이러한 구성 요소는 리소스 프로비저닝, 모니터링, 유지 관리 등 필수 작업을 처리하며 NetApp ONTAP 툴 for VMware와 같은 타사 플러그인 통합 기능도 제공합니다. 관리 도메인은 VCF 설치 어플라이언스를 사용하여 배포하여 모범 사례를 준수하거나, 기존 vCenter 환경을 VCF 관리 도메인으로 변환할 수 있습니다.
* *워크로드 도메인* – 워크로드 도메인은 특정 운영 요구 사항, 워크로드 또는 조직에 특화된 리소스 풀로 설계되었습니다. 워크로드 도메인은 OPS Manager를 통해 간편하게 배포할 수 있으며, 복잡한 작업을 자동화하는 데 도움이 됩니다. VCF 환경 내에서 최대 24개의 워크로드 도메인을 프로비저닝할 수 있으며, 각 도메인은 애플리케이션 실행 준비가 완료된 인프라 단위를 나타냅니다. 각 워크로드 도메인은 단일 지역 배포인지 다중 지역 배포인지에 따라 자체 NSX 인프라를 보유하거나 기존 인프라를 공유할 수 있습니다.




[[storage-with-vcf]]
== VCF를 사용한 저장

도메인의 기능에서 가장 중요한 것은 도메인이 사용하는 저장 공간입니다.  VCF는 하이퍼 컨버지드 사용 사례를 위한 CPU 코어 기반 vSAN 용량을 포함하는 동시에 광범위한 외부 스토리지 솔루션도 지원합니다.  이러한 유연성은 기존 스토리지 어레이에 상당한 투자를 했거나 vSAN에서 제공하는 것 이상의 프로토콜을 지원해야 하는 기업에 매우 중요합니다.  VMware는 VCF를 통해 다양한 스토리지 유형을 지원합니다.

VCF에는 두 가지 주요 저장 유형이 있습니다.

* *주 스토리지* – 이 스토리지 유형은 새 VCF 도메인의 초기 배포 또는 기존 vCenter의 컨버지 또는 임포트 과정에서 자동으로 프로비저닝됩니다. VCF 설치 프로그램은 신규 구축 시 VSAN, FC 기반 VMFS 및 NFS를 지원하며, iSCSI 기반 VMFS, NVMe-oF를 포함한 기타 지원되는 스토리지 유형은 기존 vCenter의 컨버지 또는 임포트 과정에서 주 스토리지로 설정할 수 있습니다. ONTAP Tools for VMware vSphere는 기존 vCenter의 컨버지 또는 임포트 과정에서만 VCF 도메인의 주 스토리지를 배포하는 데 사용할 수 있습니다. 추가 클러스터 배포 또는 도메인 확장 과정에서 생성된 모든 데이터스토어는 주 스토리지로 간주됩니다. 주 스토리지는 vCenter, NSX Manager, SDDC Manager를 포함한 VCF 관리 구성 요소와 도메인 내에서 실행되는 워크로드를 호스팅하는 데 사용됩니다.
* *보조 스토리지* – 보조 스토리지는 VCF 도메인을 처음 배포하거나 기존 vCenter 환경을 통합 또는 가져온 후에 프로비저닝되는 모든 데이터스토어를 의미합니다. 보조 스토리지는 ONTAP Tools for VMware vSphere를 사용하여 VCF 도메인용 데이터스토어를 배포함으로써 생성할 수 있습니다. 보조 스토리지는 추가 용량 요구 사항, 성능 요구 사항을 충족하거나 서로 다른 스토리지 특성을 필요로 하는 특정 워크로드를 지원하기 위해 생성됩니다. 또한 고가용성을 위한 확장 클러스터를 구성하기 위해 보조 스토리지를 생성할 수도 있습니다.


*VCF 스토리지 유형 지원*

|===


| *도메인 유형* | *주요 저장소* | *보충 저장* 


| 관리 도메인 | vSAN FC NFS 3 NFS 4.1 ^2^ iSCSI ^2^ NVMe/TCP ^2^ NVMe/FC ^2^ NVMe/RDMA ^2^ | vVols (FC, iSCSI 또는 NFS) ^1^ FC NFS 3 NFS 4.1 iSCSI NVMe/TCP NVMe/FC NVMe/RDMA

[[why-ontap-for-vcf]]
== VCF에 ONTAP 이유

투자 보호 및 다중 프로토콜 지원과 관련된 사용 사례 외에도 VCF 워크로드 도메인 내에서 외부 공유 스토리지를 활용해야 하는 데에는 여러 가지 이유가 있습니다.  워크로드 도메인에 프로비저닝된 스토리지는 단순히 VM과 컨테이너를 호스팅하는 저장소일 뿐이라고 가정할 수 있습니다.  그러나 조직의 요구가 라이선스 용량을 초과하여 엔터프라이즈급 스토리지가 필요한 경우가 많습니다.  VCF 내의 도메인에 할당된 ONTAP 이 제공하는 스토리지는 배포가 쉽고 미래에도 사용할 수 있는 공유 스토리지 솔루션을 제공합니다.

image:why-ontap-for-vmware-002.png["VCF에 ONTAP 이유"]

아래에 식별된 VMware VCF의 주요 ONTAP 이점에 대한 자세한 내용은 다음을 참조하세요.link:vmw-getting-started-overview.html#why-ontap-for-vmware["VMware에 ONTAP 해야 하는 이유"] .

* 1일차부터 확장에 따른 유연성
* ONTAP 에 스토리지 작업 오프로드
* 동급 최고의 저장 효율성
* 엔터프라이즈급 데이터 가용성
* 효율적인 백업 및 복구 작업
* 전체적인 비즈니스 연속성 기능

== 요약

ONTAP 모든 작업 부하 요구 사항을 처리하는 플랫폼을 제공하며, 맞춤형 블록 스토리지 솔루션과 통합 제품을 제공하여 안정적이고 보안된 방식으로 VM과 애플리케이션에서 더 빠른 결과를 얻을 수 있도록 지원합니다.  ONTAP 고급 데이터 감소 및 이동 기술을 통합하여 데이터 센터의 설치 공간을 최소화하는 동시에 중요한 워크로드를 온라인 상태로 유지하기 위해 엔터프라이즈 수준의 가용성을 보장합니다.  또한 AWS, Azure 및 Google은 VMware-in-the-Cloud 제품의 일부로 VMware 클라우드 기반 클러스터의 vSAN 스토리지를 향상시키기 위해 NetApp 기반 외부 스토리지를 지원합니다.  전반적으로 NetApp의 뛰어난 기능으로 인해 VMware Cloud Foundation 배포에 더 효과적인 선택이 됩니다.
