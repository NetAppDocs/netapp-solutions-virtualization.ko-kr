= VCF 워크로드 도메인의 주 스토리지로 ONTAP의 NFS 데이터스토어 사용
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
이 사용 사례에서는 VMware Cloud Foundation(VCF) 워크로드 도메인의 기본 스토리지 솔루션으로 ONTAP에 NFS 데이터스토어를 구성하는 절차를 설명합니다. 이 절차는 필요한 구성 요소, 구성 단계 및 배포 프로세스를 요약합니다.



[[benefits-of-nfs]]
== NFS의 이점

*간단하고 사용 용이성:* NFS는 설정과 관리가 간단하므로 빠르고 쉽게 파일을 공유해야 하는 환경에 매우 적합한 선택입니다.

*확장성:* ONTAP의 아키텍처는 NFS가 효율적으로 확장되어 인프라를 크게 변경하지 않고도 증가하는 데이터 요구 사항을 지원할 수 있도록 해줍니다.

*유연성:* NFS는 광범위한 애플리케이션과 작업 부하를 지원하므로 가상화된 환경을 포함한 다양한 사용 사례에 다양하게 활용할 수 있습니다.



[[scenario-overview]]
== 시나리오 개요

이 시나리오에서는 다음과 같은 상위 수준 단계를 다룹니다.

* NFS 트래픽을 위한 논리적 인터페이스(LIF)를 갖춘 스토리지 가상 머신(SVM)을 생성합니다.
* ONTAP 스토리지 가상 머신(SVM)에 대한 네트워킹을 확인하고 NFS 트래픽을 전송하는 논리적 인터페이스(LIF)가 있는지 확인합니다.
* vSphere 호스트가 NFS 볼륨에 액세스할 수 있도록 내보내기 정책을 생성합니다.
* ONTAP 스토리지 시스템에 NFS 볼륨을 생성합니다.
* SDDC Manager에서 NFS 및 vMotion 트래픽을 위한 네트워크 풀을 만듭니다.
* vCenter에서 VCF 워크로드 도메인에 사용할 호스트를 구성합니다.
* NFS 데이터스토어를 주 스토리지로 사용하여 VCF Ops에 VCF 워크로드 도메인을 배포합니다.
* 클러스터 이미지에 VMware VAAI용 NetApp NFS 플러그인이 포함되어 있는지 확인하십시오.



NOTE: 이 솔루션은 NetApp AFF, AFX 및 FAS를 포함하여 NFS 스토리지를 지원하는 ONTAP 플랫폼에 적용 가능합니다.



[[prerequisites]]
== 필수 조건

이 시나리오에서는 다음 구성 요소와 구성이 사용됩니다.

* NetApp NFS 트래픽을 허용하도록 구성된 스토리지 가상 머신(SVM)이 있는 AFF, AFX 또는 FAS 스토리지 시스템.
* NFS 트래픽을 전달하고 SVM과 연관되는 논리적 인터페이스(LIF)가 IP 네트워크에 생성되었습니다.
* VCF 관리 도메인 배포가 완료되었으며 VCF Operations Manager 인터페이스에 액세스할 수 있습니다.
* VCF 관리 네트워크에서 통신이 가능하도록 구성된 vSphere 호스트가 최소 2대 이상 필요합니다.
* 이 목적으로 설정된 VLAN 또는 네트워크 세그먼트의 vMotion 및 NFS 스토리지 트래픽을 위해 예약된 IP 주소입니다.



NOTE: VCF 워크로드 도메인을 배포할 때 VCF는 NFS 서버와의 연결성을 검증합니다. 이 검증은 NFS IP 주소를 사용하는 추가 vmkernel 어댑터가 추가되기 전에 vSphere 호스트의 관리 어댑터를 사용하여 수행됩니다. 따라서 검증이 진행될 수 있도록 1) 관리 네트워크가 NFS 서버로 라우팅 가능하거나, 2) NFS 데이터스토어 볼륨을 호스팅하는 SVM에 관리 네트워크에 대한 LIF가 추가되어 있는지 확인해야 합니다.

ONTAP 스토리지 시스템 구성에 대한 정보는 다음을 참조하세요.link:https://docs.netapp.com/us-en/ontap["ONTAP 9 문서"] 센터.

VCF 구성에 대한 자세한 내용은 link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1.html["VMware Cloud Foundation 문서"]을 참조하십시오.

vSphere 클러스터에서 NFS를 사용하는 방법에 대한 자세한 내용은 다음을 참조하세요.link:vmw-vvf-overview.html["vSphere 8용 NFS v3 참조 가이드"] .

[[deployment-steps]]
== 배포 단계

NFSv3 데이터스토어를 주 스토리지로 사용하는 VCF 워크로드 도메인을 배포하려면 다음 단계를 완료하십시오.

.ONTAP SVM에 대한 네트워킹 확인
[%collapsible%open]
====
ONTAP 스토리지 클러스터와 워크로드 도메인 간에 NFS 트래픽을 전송할 네트워크에 필요한 논리적 인터페이스가 설정되었는지 확인하십시오.

. ONTAP 시스템 관리자에서 왼쪽 메뉴의 *스토리지 VM*으로 이동하여 NFS 트래픽에 사용할 SVM을 클릭합니다. *개요* 탭의 *네트워크 인터페이스*에서 *NFS* 레이블 위의 숫자를 클릭합니다. 목록에서 필요한 LIF IP 주소가 나열되어 있는지 확인합니다.
+
image:vmw-vcf-viwld-principal-nfs-001.png["SVM용 NFS LIF 확인"]



또는 다음 명령을 사용하여 ONTAP CLI에서 SVM과 연관된 LIF를 확인하세요.

[source, cli]
----
network interface show -vserver <SVM_NAME>
----
. vSphere 호스트가 ONTAP NFS 서버와 통신할 수 있는지 확인하십시오. vSphere 호스트에 SSH를 통해 로그인하고 SVM LIF에 ping을 보내십시오.


[source, cli]
----
vmkping <IP Address>
----

NOTE: 워크로드 도메인을 배포할 때 VCF는 NFS 서버와의 연결을 검증합니다. 이 검증은 NFS IP 주소가 포함된 추가 vmkernel 어댑터가 추가되기 전에 vSphere 호스트의 관리 어댑터를 사용하여 수행됩니다. 따라서 검증이 진행될 수 있도록 1) 관리 네트워크가 NFS 서버로 라우팅 가능하거나, 2) NFS 데이터스토어 볼륨을 호스팅하는 SVM에 관리 네트워크에 대한 LIF가 추가되어 있는지 확인해야 합니다.

====
.NFS 볼륨 공유를 위한 내보내기 정책 생성
[%collapsible%open]
====
ONTAP System Manager에서 내보내기 정책을 만들어 NFS 볼륨에 대한 액세스 제어를 정의합니다.

. ONTAP 시스템 관리자에서 왼쪽 메뉴의 *스토리지 VM*을 클릭하고 목록에서 SVM을 선택합니다.
. *설정* 탭에서 *내보내기 정책*을 찾아 화살표를 클릭하여 액세스합니다.
+
image:vmw-vcf-viwld-principal-nfs-002.png["수출 정책 액세스"]

+
{nbsp}

. [추가]를 클릭하면 [새 내보내기 정책] 창이 열립니다. 정책 이름을 입력하고 [새 규칙 추가] 버튼을 클릭한 다음 [+ 추가] 버튼을 클릭하여 새 규칙 추가를 시작합니다.
+
image:vmw-vcf-viwld-principal-nfs-003.png["새로운 수출 정책"]

+
{nbsp}

. 규칙에 포함할 IP 주소, IP 주소 범위 또는 네트워크를 입력하십시오. *SMB/CIFS* 및 *FlexCache* 확인란의 선택을 해제하고 아래에서 액세스 세부 정보를 선택하십시오. vSphere 호스트 액세스의 경우 UNIX 확인란을 선택하는 것으로 충분합니다.
+
image:vmw-vcf-viwld-principal-nfs-004.png["새 규칙 저장"]

+

NOTE: 워크로드 도메인을 배포할 때 VCF는 NFS 서버와의 연결성을 검증합니다. 이 검증은 NFS IP 주소와 함께 추가 vmkernel 어댑터가 추가되기 전에 vSphere 호스트의 관리 어댑터를 사용하여 수행됩니다. 따라서 검증이 진행될 수 있도록 내보내기 정책에 VCF 관리 네트워크가 포함되어 있는지 확인해야 합니다.

. 모든 규칙을 입력한 후 *저장* 버튼을 클릭하여 새 내보내기 정책을 저장합니다.
. 또는 ONTAP CLI에서 내보내기 정책과 규칙을 만들 수 있습니다.  ONTAP 설명서에서 내보내기 정책을 만들고 규칙을 추가하는 단계를 참조하세요.
+
** ONTAP CLI를 사용하여link:https://docs.netapp.com/us-en/ontap/nfs-config/create-export-policy-task.html["수출 정책 만들기"] .
** ONTAP CLI를 사용하여link:https://docs.netapp.com/us-en/ontap/nfs-config/add-rule-export-policy-task.html["내보내기 정책에 규칙 추가"] .




====
.NFS 볼륨 생성
[%collapsible%open]
====
워크로드 도메인 배포에서 데이터 저장소로 사용할 ONTAP 스토리지 시스템에 NFS 볼륨을 만듭니다.

. ONTAP 시스템 관리자의 왼쪽 메뉴에서 *저장소 > 볼륨*으로 이동한 다음 *+추가*를 클릭하여 새 볼륨을 만듭니다.
+
image:vmw-vcf-viwld-principal-nfs-005.png["새로운 볼륨 추가"]

+
{nbsp}

. 볼륨의 이름을 추가하고, 원하는 용량을 입력하고, 볼륨을 호스팅할 스토리지 VM을 선택합니다.  계속하려면 *추가 옵션*을 클릭하세요.
+
image:vmw-vcf-viwld-principal-nfs-006.png["볼륨 세부 정보 추가"]

+
{nbsp}

. 액세스 권한에서 VCF 관리 네트워크 또는 IP 주소와 NFS 서버와 NFS 트래픽의 검증에 사용될 NFS 네트워크 IP 주소가 포함된 내보내기 정책을 선택합니다.
+
image:vmw-vcf-viwld-principal-nfs-007.png["볼륨 세부 정보 추가"]

+
+ {nbsp}

+

NOTE: VCF 워크로드 도메인을 배포할 때 VCF는 NFS 서버와의 연결성을 검증합니다. 이 검증은 NFS IP 주소를 사용하는 추가 vmkernel 어댑터가 추가되기 전에 vSphere 호스트의 관리 어댑터를 사용하여 수행됩니다. 따라서 검증이 진행될 수 있도록 1) 관리 네트워크가 NFS 서버로 라우팅 가능하거나, 2) NFS 데이터스토어 볼륨을 호스팅하는 SVM에 관리 네트워크에 대한 LIF가 추가되어 있는지 확인해야 합니다.

. 또는 ONTAP CLI에서 NFS 볼륨을 생성할 수도 있습니다. 자세한 내용은 ONTAP 명령 설명서의 link:https://docs.netapp.com/us-en/ontap-cli/volume-create.html["volume create"] 명령을 참조하십시오.

[[vcf-workload-domain-default-cluster]]
=== VCF 워크로드 도메인 - 기본 클러스터

관리 도메인이 실행된 후에는 VCF 워크로드 도메인을 생성할 수 있습니다.

* VCF Ops UI를 사용합니다. vSphere 호스트는 vCenter에 커미셔닝되고 네트워크 풀이 구성됩니다. System Manager 또는 ONTAP API를 사용하여 NFS 볼륨을 vSphere 호스트로 내보냅니다.
* 기존 vSphere 환경을 새 워크로드 도메인으로 가져옵니다. ONTAP tools for VMware vSphere 또는 System Manager 또는 ONTAP API를 사용하여 NFSv3 또는 NFS4.1 데이터스토어를 vSphere 클러스터에 배포할 수 있습니다.




[[vcf-workload-domain-additional-cluster]]
=== VCF 워크로드 도메인 - 추가 클러스터

추가 클러스터를 사용하여 워크로드 도메인을 확장하려면  https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/expand-a-workload-domain/add-a-cluster-to-a-workload-domain-using-the-sddc-manager-ui.html["VCF 도메인에 SDDC 클러스터 추가"]을 참조하십시오.

워크로드 도메인에 추가 클러스터를 추가하는 단계는 다음과 같습니다. * 호스트가 커미셔닝되고 네트워크 풀이 vCenter에 구성되어 있는지 확인합니다. * NFS 볼륨은 ONTAP 스토리지 시스템에 프로비저닝되고 추가 클러스터의 호스트로 내보냅니다. * NFS 볼륨은 추가 클러스터의 vSphere 호스트 중 하나에 마운트됩니다. * vCenter의 워크로드 도메인에서 새 SDDC 클러스터를 생성하고 마법사를 따라 추가 클러스터를 워크로드 도메인에 추가합니다.
