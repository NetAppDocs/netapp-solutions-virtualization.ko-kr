= MetroCluster를 사용하여 VCF 워크로드 도메인에 대한 스트레치 클러스터 구성
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
이 사용 사례에서는 FC, iSCSI, NVMe-oF, NFSv3 또는 NFSv4.1을 기본 데이터 저장소로 사용하는 ONTAP MetroCluster를 이용하여 VMware Cloud Foundation(VCF) 워크로드 도메인용 스트레치 클러스터를 구성하는 절차를 설명합니다. VCF는 사용자의 요구 사항에 따라 다양한 배포 옵션을 제공합니다. VCF Ops 툴을 사용하여 새로운 VCF 워크로드 도메인을 배포하거나 기존 vSphere 환경을 VCF 워크로드 도메인으로 가져올 수 있습니다. 이 문서에서는 MetroCluster 부분에 중점을 두고 배포 단계에 따라 다른 문서를 참조하도록 안내합니다.

image:vmw-vcf-vmsc-viwld-mcc-001.png["vMSC가 포함된 VCF 워크로드 도메인,width=500"]



[[introduction]]
== 소개

이 솔루션에서는 ONTAP MetroCluster를 주 데이터 저장소로 사용하여 확장형 VCF 워크로드 도메인을 구현하는 방법을 보여드리겠습니다. MetroCluster를 사용하면 ONTAP 클러스터에서 실행되는 모든 워크로드에 대한 고가용성 솔루션을 배포할 수 있습니다. 특정 워크로드에 대한 고가용성 솔루션이 필요한 경우 SnapMirror 액티브 동기화(SAN 및 NAS) 사용을 고려하십시오. SnapMirror 액티브 동기화(SAN)는 일관성 그룹 수준에서 작동하고 SnapMirror 액티브 동기화(NAS)는 SVM 수준에서 작동합니다. 자세한 내용은 link:vmw-vcf-vmsc-viwld-smas.html["SnapMirror Active Sync(SAN 및 NAS)를 사용하여 VCF 워크로드 도메인용 스트레치 클러스터 구성"]을 참조하십시오.



[[prerequisites]]
== 필수 조건

이 시나리오에는 다음과 같은 구성 요소와 구성이 필요합니다.

* 지원되는 ONTAP MetroCluster 구성
* 선호하는 스토리지 프로토콜로 구성된 스토리지 가상 머신(SVM).
* 스토리지 트래픽을 전달하기 위해 논리 인터페이스(LIF)가 생성되었으며, 이는 SVM과 연결되어 있습니다.




[[high-level-overview]]
== 개괄적인 내용

MetroCluster는 애그리게이트 수준에서 처리되는 워크로드에 대한 고가용성 솔루션을 제공합니다. SVM은 MetroCluster의 결함 도메인 중 하나에서 활성화됩니다.

다음은 MetroCluster 구성을 보여주는 시스템 관리자의 샘플 스크린샷입니다.image:vmw-vcf-vmsc-mgmt-mcc-015.png["4노드 MetroCluster IP"]

그리고 여기에 두 가지 단층 도메인의 SVM 네트워크 인터페이스가 있습니다.image:vmw-vcf-vmsc-mgmt-mcc-013.png["Fault Domain 1의 SVM 네트워크 인터페이스"]

image:vmw-vcf-vmsc-mgmt-mcc-014.png["Fault Domain 2의 SVM 네트워크 인터페이스"]

[참고] SVM은 MetroCluster 의 오류 도메인 중 하나에서 활성화됩니다.

image:vmw-vcf-vmsc-mgmt-mcc-016.png["오류 도메인 1의 SVM"]

image:vmw-vcf-vmsc-mgmt-mcc-017.png["Fault Domain 2의 SVM"]

참조 https://support.broadcom.com/web/ecx/search?searchString=vMSC%20with%20MetroCluster["MetroCluster 를 갖춘 vMSC"].

통합 프로세스에 대한 개요는 VMware 설명서를 참조하십시오: https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/deployment/converging-your-existing-vsphere-infrastructure-to-a-vcf-or-vvf-platform-.html["기존 가상 인프라를 VCF로 통합하기"].

ONTAP 스토리지 시스템 구성에 대한 정보는 다음을 참조하세요.link:https://docs.netapp.com/us-en/ontap["ONTAP 9 문서"] 센터.

VCF 구성에 대한 자세한 내용은 link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1.html["VMware Cloud Foundation 9.1 설명서"]을 참조하십시오.



[[deployment-steps-for-greenfield-vcf-workload-domain-with-metrocluster]]
== MetroCluster를 사용하는 그린필드 VCF 워크로드 도메인 배포 단계

그린필드 배포(기존 VCF 구성 요소가 없는 새로운 배포)의 경우 VCF Ops 툴을 사용하여 워크로드 도메인을 배포합니다. 이 시나리오에서는 FC의 VMFS 및 NFSv3가 지원됩니다.

FC에서 VMFS를 사용하는 경우 link:vmw-vcf-viwld-principal-fc.html["FC 기반 VMFS 데이터 저장소가 있는 VCF 워크로드 도메인(ONTAP 주 스토리지)"] 자세한 내용을 참조하십시오. NFSv3의 경우 link:vmw-vcf-viwld-principal-nfs.html["NFSv3 데이터스토어가 있는 VCF 워크로드 도메인(ONTAP를 주 스토리지로 사용)"] 자세한 내용을 참조하십시오.



[[deployment-steps-for-brownfield-vcf-workload-domain-with-metrocluster]]
== Brownfield VCF 워크로드 도메인과 MetroCluster의 배포 단계

브라운필드 배포는 기존 vSphere 환경을 VCF 워크로드 도메인으로 가져오려는 시나리오입니다.

iSCSI, NVMe-oF 및 NFSv4.1의 경우 vCenter(가급적 ONTAP 툴 사용)에서 설정한 후 VCF Ops 툴을 사용하여 워크로드 도메인으로 가져와야 합니다. 자세한 내용은 link:https://techdocs.broadcom.com/us/en/vmware-cis/vcf/vcf-9-0-and-later/9-1/building-your-private-cloud-infrastructure/working-with-workload-domains/import-an-existing-vcenter-to-create-a-workload-domain.html["기존 vCenter를 가져와 워크로드 도메인을 생성합니다."]을 참조하십시오.
